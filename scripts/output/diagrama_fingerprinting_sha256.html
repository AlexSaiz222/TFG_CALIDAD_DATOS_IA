¿Qué resuelve el fingerprinting?

Cada ejecución detecta issues, pero la base de datos les asigna IDs distintos. Para saber si un problema es nuevo, sigue presente o se ha resuelto entre dos runs hace falta un identificador estable y determinista de cada issue, independiente de su ID de fila. Eso es el fingerprint. Avanza paso a paso.

Por qué SHA-256: es determinista (misma entrada → mismo hash siempre), de longitud fija y con buena dispersión, así que entradas casi iguales dan hashes muy distintos. No se usa por seguridad sino como ID reproducible. Se trunca a [:16] (64 bits): suficiente para identificar issues dentro de un proyecto con probabilidad de colisión despreciable. El valor de la métrica y los recuentos NO entran en el hash a propósito: así el mismo problema lógico conserva su fingerprint aunque cambie cuántas filas afecta.
