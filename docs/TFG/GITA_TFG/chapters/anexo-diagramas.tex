\chapter{Diagramas del sistema}
\label{anx:diagramas}

Este anexo recoge las descripciones estructuradas y las representaciones gráficas
de los principales diagramas \ac{UML} y del modelo relacional del sistema. El diagrama de arquitectura
a alto nivel se incluye en el cuerpo del documento (Figura~\ref{fig:diagrama-arquitectura});
el resto de diagramas se incluyen y detallan en este anexo.

\section{Diagrama de paquetes}

La arquitectura del sistema se organiza en seis paquetes principales, representados
gráficamente en la Figura~\ref{fig:diagrama-paquetes}. La descripción detallada de cada paquete
es la siguiente:

\begin{figure}[H]
  \centering
  \includegraphics[width=0.9\textwidth,keepaspectratio]{img/diagrama_paquetes.png}
  \caption{Diagrama de paquetes del sistema (Frontend y Backend)}
  \label{fig:diagrama-paquetes}
\end{figure}

\begin{itemize}
  \item \textbf{Presentación} (\emph{frontend} Next.js + React):
    \texttt{pages/} (rutas), \texttt{components/} (más de 40 componentes
    React reutilizables), \texttt{services/} (cliente \ac{API} con Axios)
    y \texttt{contexts/} (estado global: \texttt{AuthContext},
    \texttt{NotificationContext}, \texttt{SidebarContext},
    \texttt{LanguageContext}).

  \item \textbf{API REST} (\emph{backend} Flask, 10 \emph{blueprints}):
    siete \emph{blueprints} funcionales (\texttt{auth}, \texttt{projects},
    \texttt{datasets}, \texttt{metrics}, \texttt{evaluations},
    \texttt{admin}, \texttt{patterns}) y tres de organización técnica
    \ac{REST} (\texttt{project\_metrics}, \texttt{project\_datasets},
    \texttt{dashboard}).

  \item \textbf{Servicios} (lógica de negocio):
    \texttt{EvaluationService} orquesta el flujo completo de evaluación;
    \texttt{HybridEvaluationService} permite ejecución asíncrona o síncrona
    según disponibilidad de Celery; \texttt{DatasetService} parsea archivos
    y extrae el esquema; \texttt{MinioService} abstrae el almacenamiento
    S3; \texttt{ExportService} genera informes a partir de los
    resultados.

  \item \textbf{Motor de métricas} (\texttt{services/metrics/}, núcleo
    extensible): \texttt{BaseMetric} (clase base abstracta),
    \texttt{MetricResult} (\emph{dataclass}) y \texttt{METRIC\_REGISTRY}
    (registro de \emph{plugins}).  Implementa siete métricas evaluables
    (\texttt{completeness}, \texttt{uniqueness}, \texttt{syntactic\_accuracy},
    \texttt{logical\_consistency}, \texttt{class\_balance},
    \texttt{currentness}, \texttt{diversity}) y la clase
    \texttt{OutliersMetric}, usada exclusivamente desde el módulo de
    perfilado \ac{EDA}.

  \item \textbf{Datos} (modelos SQLAlchemy \ac{ORM}, 11 tablas):
    \texttt{User}, \texttt{Project}, \texttt{Dataset}, \texttt{Metric},
    \texttt{MetricTemplate}, \texttt{Evaluation}, \texttt{Issue}
    (modelo original) y \texttt{AnalysisRun}, \texttt{DataQualityIssue},
    \texttt{QualityGate}, \texttt{ValidationPattern} (subsistema de análisis incremental).

  \item \textbf{Infraestructura externa}: PostgreSQL\,14, MinIO,
    Redis, Celery Worker, Celery Beat y Flower, orquestados con
    Docker~Compose.
\end{itemize}

Las dependencias siguen una topología estrictamente vertical
(\emph{depends-on}): cada capa solo depende de la inmediatamente inferior,
salvo la conexión adicional Celery~Worker~$\to$~Servicios para la ejecución
asíncrona de tareas.

    \begin{itemize}
      \item UC-01: Gestionar proyectos (crear, editar, eliminar, listar)
      \item UC-02: Gestionar datasets (cargar, versionar, marcar \ac{PII})

      \item UC-08: Detectar evaluaciones atascadas (\emph{watchdog}: hilo del backend Flask)
    \end{itemize}
\end{itemize}

\section{Diagrama de secuencia: Ejecución de evaluación}

La ejecución de un análisis de calidad asíncrono (Sonar-Lite) sigue el flujo representado
gráficamente en la Figura~\ref{fig:diagrama-secuencia}. Los pasos correspondientes
al camino feliz se describen a continuación:

\begin{figure}[H]
  \centering
  \includegraphics[width=\textwidth,keepaspectratio]{img/diagrama_secuencia.png}
  \caption{Diagrama de secuencia del flujo de ejecución de una evaluación}
  \label{fig:diagrama-secuencia}
\end{figure}

\begin{enumerate}
  \item \textbf{Frontend} → POST
    \texttt{/api/evaluations/projects/<project\_id>/analyze} (con
    \texttt{dataset\_id} y la configuración de métricas)
  \item \textbf{Backend} → Crea un \texttt{AnalysisRun} (estado
    \texttt{PENDING}) y una \texttt{Evaluation} legacy asociada por
    compatibilidad
  \item \textbf{Backend} → Encola la tarea Celery \texttt{run\_evaluation}
  \item \textbf{Backend} → Responde \texttt{202 Accepted} con
    \texttt{\{analysis\_run\_id\}}
  \item \textbf{Frontend} → Polling GET
    \texttt{/api/evaluations/analysis/<run\_id>/status} cada pocos segundos
  \item \textbf{Celery Worker} → Marca el \texttt{AnalysisRun} como
    \texttt{RUNNING} y descarga el \emph{dataset} de MinIO
  \item \textbf{Celery Worker} → Invoca
    \texttt{EvaluationService.run\_evaluation()}
  \item \textbf{EvaluationService} → Ejecuta cada métrica configurada
  \item \textbf{EvaluationService} → Calcula el \emph{Quality Score}
  \item \textbf{EvaluationService} → Genera \emph{fingerprints} y compara
    con el \emph{baseline}
  \item \textbf{EvaluationService} → Evalúa el \emph{Quality Gate}
  \item \textbf{Celery Worker} → Persiste resultados y marca el
    \texttt{AnalysisRun} (y la \texttt{Evaluation}) como
    \texttt{COMPLETED}
  \item \textbf{Frontend} → Detecta \texttt{COMPLETED} y redirige a la
    página de resultados
\end{enumerate}

\section{Diagrama de clases: Motor de métricas}

La jerarquía de clases principales y servicios del motor de métricas se representa
en la Figura~\ref{fig:diagrama-clases}. La descripción de los componentes principales se detalla a continuación.

\begin{figure}[H]
  \centering
  \includegraphics[width=0.9\textwidth,keepaspectratio]{img/diagrama_clases.png}
  \caption{Diagrama de clases del motor de métricas y los servicios asociados}
  \label{fig:diagrama-clases}
\end{figure}

Jerarquía de clases del motor de métricas
(\texttt{backend/services/metrics/}):

\begin{itemize}
  \item \textbf{BaseMetric} (clase base abstracta, \texttt{ABC})
    \begin{itemize}
      \item Atributo de clase: \texttt{log\_prefix: str} (identificador
        usado en mensajes de \emph{log}).
      \item Método abstracto:
        \texttt{evaluate(df, parameters, dataset, evaluation\_id, metrics\_map)
        → MetricResult}.
      \item Utilidades estáticas compartidas:
        \texttt{calculate\_dynamic\_severity()} (severidad por distancia al
        umbral, especializada por tipo de métrica),
        \texttt{infer\_column\_type()} (clasificación semántica:
        ID/categórica/numérica/texto), \texttt{mask\_sensitive()}
        (enmascarado de valores \ac{PII}),
        \texttt{generate\_histogram()} y \texttt{apply\_null\_patterns()}.
    \end{itemize}
  \item \textbf{CompletenessMetric} hereda BaseMetric
  \item \textbf{UniquenessMetric} hereda BaseMetric
  \item \textbf{OutliersMetric} hereda BaseMetric (uso exclusivo del módulo
    de perfilado; no se registra en \texttt{METRIC\_REGISTRY})
  \item \textbf{SyntacticAccuracyMetric} hereda BaseMetric
  \item \textbf{LogicalConsistencyMetric} hereda BaseMetric
  \item \textbf{ClassBalanceMetric} hereda BaseMetric
  \item \textbf{CurrentnessMetric} hereda BaseMetric
  \item \textbf{DiversityMetric} hereda BaseMetric
  \item \textbf{MetricResult} (\emph{dataclass}): \texttt{metric\_id: str},
    \texttt{score: Optional[float]}, \texttt{results: dict[str, Any]}
    (datos detallados para persistencia en \texttt{AnalysisRun.results}),
    \texttt{issues: list[dict[str, Any]]} (incidencias en el formato
    esperado por \texttt{EvaluationService}).
  \item \textbf{METRIC\_REGISTRY}: \texttt{dict[str, Type[BaseMetric]]} con
    las siete métricas evaluables registradas.
\end{itemize}
